# ADR-0019.3: Eugene ops signer becomes Patrick Dills; auto-override actor repaired at both sites

**Date:** 2026-08-11
**Status:** Accepted
**Extends:** ADR-0019 (Bonus Management System), ADR-0019.1 (Bi-weekly cadence), ADR-0019.2 (Eugene enablement)
**Amends:** ADR-0023 (Patrick separation-of-duties exclusion), ADR-0028 (amendment-workflow carve-out)

## Context

Two things are decided here. They arrived in the same session because the first
one surfaced the second, but they are independent and are recorded as such.

### The role change

ADR-0019.2 §2 configured the Eugene signature chain as facility = Rick
Albritton, ops = Kelsey Ruhland. That held until 2026-08-08, when Kelsey's
availability ended and Shannon Rockwell was installed in the ops slot as cover
(recorded in `audit_log` under actor label
`system:approver-swap (Bill instruction 2026-08-08: Shannon replaces Kelsey effective today)`).

On 2026-08-11 Bill directed that **Patrick Dills** take the Eugene ops-signer
slot, permanently, replacing Shannon.

The instruction as first relayed was "remove Kelsey, install Patrick." That
premise was already stale — Kelsey had held no slot for three days. Executing it
literally would have removed Shannon, whom the instruction never mentioned. The
change was therefore held and re-confirmed against the audit trail before being
applied. This is worth recording because the failure mode is silent: an
assignment swap phrased in terms of the _departing_ person cannot detect that
someone else has since taken the seat.

### The latent defect the role change uncovered

While verifying the chain, both sites' `auto_override_actor_user_id` was found
pointing at user `45a9d1d0…` (`operations@svdp.us`) — an account seeded
`is_active = false` **on purpose**, because it is an import/automation alias
rather than a login identity.

The t3 08:30 PT auto-override refuses to sign as an inactive actor (the
`actorUnavailable` guard in `src/lib/bonus/escalation.ts`). So the auto-override
— described in ADR-0019.1 §4 as "the load-bearing mechanism for hitting the 9:00
AM deadline reliably" — was **dead at both sites**, and had been since at least
the 2026-07-07 payroll incident.

The 2026-07-07 `audit_log` entry claims the repair was made:

> payroll incident 2026-07-07: chain referenced deactivated duplicate Bill user
> 45a9d1d0 — t3 auto-override actorUnavailable, Eugene deadline missed;
> repointed all override actors at active admin user

The columns did not reflect it a month later. **Root cause: `prisma/seed.mjs`
carried an alias `SIGNATURE_CHAIN_EMAIL_ALIASES['bill.barnard@svdp.us'] = 'operations@svdp.us'`,**
added because `bill.barnard@svdp.us` was not seeded in `users.csv`. Every
`db:seed` run therefore re-resolved the chain's Bill to the deliberately-dead
account and silently re-broke the safety net. The manual repair was correct; the
seed reverted it.

## Decision

### 1. Patrick Dills holds the Eugene ops-signer slot

Effective 2026-08-11. Rick Albritton keeps facility. `ops_override_actor_ids`
stays Bill-only. Patrick replaces Shannon in `facility_override_actor_ids`,
preserving the ADR-0019.2 §2 asymmetry (admin-or-peer may override facility;
admin only may override ops).

No code change was required. Approver identity is data — `bonus_signature_chains`
is the configuration surface, exactly as ADR-0019.2 §2 intended — and the chain
cache TTL is 30s, so the change went live without a deploy or restart.

### 2. This reverses the ADR-0023 separation-of-duties exclusion, knowingly

ADR-0023 (T-312) deliberately kept Patrick out of every Eugene chain slot
because he is also a Eugene `BonusEmployee`. That reasoning was sound and is not
being declared wrong; it is being **overridden by the operator**, who owns the
staffing constraint.

The residual risk, stated plainly rather than buried: Patrick is now the default
amendment approver for Eugene, which includes amendments to entries containing
his own historical bonus rows (119 entries, 2025-01-07 → 2026-01-14; his
`bonus_employees` row is `is_active = false`, so he accrues nothing in current or
future periods). The DB CHECK prevents requester == approver, not
approver-has-an-interest. Mitigations already in place: every amendment writes an
audit row; approve/reject notifies Bill; and admin override remains available.

### 3. The auto-override actor is repaired, and the seed can no longer re-break it

Both sites' `auto_override_actor_user_id`, `ops_override_actor_ids` and
`facility_override_actor_ids` now reference `c6a6ca68…` (`bill.barnard@svdp.us`,
active admin) instead of the dead `45a9d1d0…`.

The data fix alone would have been reverted by the next `db:seed`, so the seed is
fixed at the root:

- `bill.barnard@svdp.us` is now seeded in `prisma/seed/users.csv` as an active
  admin, with field values mirroring the live prod row (`is_super_admin=true`) so
  a re-seed cannot downgrade the account.
- The `bill.barnard@svdp.us → operations@svdp.us` alias is **removed** from
  `prisma/seed.mjs`, with a comment recording why it must not be reintroduced.
- `prisma/seed/bonus_signature_chains.csv` now names Patrick for Eugene ops, so
  a re-seed reinforces the new chain instead of reverting it to Kelsey.

## Alternatives considered

- **Apply "remove Kelsey, install Patrick" literally.** Rejected — it would have
  silently evicted Shannon. The audit trail, not the instruction's wording, is
  the authority on who currently holds a role.
- **Repair the override actor in the DB only.** Rejected — that is precisely what
  was done on 2026-07-07, and the seed undid it. A data fix without the seed fix
  is a fix with a timer on it.
- **Point the chain at `operations@svdp.us` and activate that account.**
  Rejected — it is the historical-import actor; activating it would make an
  automation alias a login identity and muddy every audit trail that
  distinguishes them.
- **Keep Shannon and decline the change on separation-of-duties grounds.**
  Rejected — the conflict is real but it is the operator's call, and it is now
  documented rather than silently absorbed.
- **Rename the `patrick_or_other_non_chain_manager` error string.** Deferred —
  it is returned as the `error` field by `/api/bonus/amendments` and is part of
  the HTTP contract. Renaming it is a breaking change and should not ride along
  with a staffing change.

## Consequences

- Patrick sees the "Pending Amendments" nav link and the ops signature panel at
  `/bonus/months/[id]`. Kelsey and Shannon no longer do at Eugene.
- Rick's amendment requests now route to Patrick; Patrick's route to Rick.
- The 08:30 PT auto-override is live again at **both** sites. Woodland was
  carrying the same dead actor and was repaired in the same transaction — it was
  one payroll morning away from the identical failure.
- Signature-request emails for the Eugene ops slot go to
  `patrick.dills@svdp.us`. Note the ADR-0019.1 behaviour that a signer receives
  **one** email and no reminders; all later escalation is ntfy to Bill.
- Shannon Rockwell keeps her account, `manager` role, Eugene site access and all
  AP duties. Only her bonus-chain membership changed. She remains a Eugene
  bonus daily-report recipient.
- The next `db:seed` now reinforces this configuration. Before this ADR it would
  have reverted the Eugene ops signer to Kelsey **and** re-killed the
  auto-override at both sites.
- Still open, deliberately not built here: the ADR-0019.1 §4 "override actor
  available" health pill does not exist (see ADR-0019.1 Amendment 2). Until it
  does, a dead override actor is only detectable at 08:30 PT on payroll morning,
  thirty minutes before the deadline. This defect class has now occurred twice.
